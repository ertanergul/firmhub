## 1. Inputs & Verified Repository Facts

| Fact | Consequence |
|---|---|
| `public/robots.txt` exists (static, allow all) | Web servers serve static files before PHP, so **every tenant host would receive the same static file**. It must be replaced by a dynamic route in Phase 3 (§5.1) |
| `public/favicon.ico`, `favicon.svg`, `apple-touch-icon.png` are static platform icons | Requested by browsers at `/favicon.ico` on tenant hosts too. Tenant pages declare their own icon links; the static file is only a fallback (§4.6) |
| `vite.config.js` inputs: `resources/css/app.css`, `resources/js/app.js` (dashboard) | Themes need their own Vite entries (0.5 TH-3) |
| Fonts via `laravel-vite-plugin/fonts` `bunny(...)` and the `@fonts` directive | Whether this downloads and self-hosts the fonts at build time or links to the Bunny CDN **must be verified**; public themes require self-hosted fonts (0.5 TH-4) |
| `partials/head.blade.php` loads Vite dashboard bundle and `@fluxAppearance` | Public theme layouts must not include this partial |
| Build output in `public/build` with root-relative URLs | Assets load on tenant hosts from the same host (§7.5) |

## 2. Public Website vs Dashboard Responsibilities

| Aspect | Public site (tenant host) | Dashboard & preview (platform host) |
|---|---|---|
| Purpose | Present published company content to visitors | Manage companies, content, publishing |
| Rendering | Server-rendered Blade theme views via `SiteRenderer` | Livewire 4 + Flux pages |
| JavaScript | None required (§6) | Livewire / Alpine (bundled by Livewire) |
| CSS | Theme bundle (`resources/css/themes/{key}.css`) | `resources/css/app.css` + Flux |
| Session & cookies | **None** (stateless) | Session, CSRF, auth cookies (host-only) |
| Authentication | None | Required + verified email |
| Indexing | `index, follow` when publicly visible | `noindex` everywhere (incl. preview) |
| Caching | Public, short-lived, validated (§7.4) | `private, no-store` for authenticated pages |
| Error pages | Context-aware tenant or generic pages (§5.4) | Starter-kit / platform error pages |
| Routes | `routes/tenant.php` (0.4 §3.1) | `routes/web.php`, `routes/settings.php` |

## 3. Public Rendering Architecture

### 3.1 Tenant routes (MVP)

| Method & path | Purpose | Response |
|---|---|---|
| `GET /` | Single-page site | `200` HTML |
| `GET /privacy` | Privacy / data processing notice (0.5 §3.2) | `200` HTML, `noindex, follow` (S-2) |
| `POST /contact` | Contact form submission | `303` redirect on success; `422` re-rendered page on validation errors; `429` when rate-limited |
| `GET /robots.txt` | Per-host robots directives | `200` text |
| `GET /sitemap.xml` | Per-host sitemap | `200` XML |
| Any other path on a visible site | — | `404` with tenant-themed page (S-6) |

All tenant routes pass `ResolvePublicSite` (0.4 §3.3); hosts that do not resolve to a publicly visible site receive the generic `404` (0.4 §6).

### 3.2 Middleware stack: stateless public group

The public group uses a **minimal, session-less middleware stack**: no `StartSession`, no `ShareErrorsFromSession`, no CSRF cookie, no auth. Benefits:

- No cookies are set for visitors (privacy, KVKK/GDPR; no cookie banner needed for strictly necessary functionality).
- Responses are cacheable by browsers and proxies (§7.4).
- No session storage load from anonymous traffic.

### 3.3 Contact form without a session

The contact form is anonymous; CSRF protection exists to stop forged requests made with a victim's authenticated session, which does not exist here. The real threats are spam and abuse, handled by (details in 0.7):

| Control | Purpose |
|---|---|
| Signed form token (HMAC over site ID + issue time, rendered in the form) | Proves the form was rendered by FirmHub for this site; enforces minimum fill time (e.g. ≥ 3 s) and maximum age (e.g. 2 h) |
| Honeypot field | Catches naive bots |
| Rate limiting per IP + site (cache-based) | Abuse prevention; `429` |
| `Origin` / `Referer` same-host check | Rejects cross-site form posts |
| Server-side validation and length limits | Data quality, storage abuse |

Feedback without flash sessions:

- **Success:** `303` redirect to `/?contact=sent#contact` (Post/Redirect/Get); the page shows a confirmation when the parameter is present. No personal data in the URL.
- **Validation errors:** the page is re-rendered directly with errors and previous input (`422`), no redirect.

The `POST /contact` route is excluded from CSRF verification only because it runs in the session-less group; this exception is documented and limited to that route (S-7).

### 3.4 Livewire usage boundaries

| Context | Livewire |
|---|---|
| Public site (MVP) | **Not used.** No Livewire or Alpine scripts on public pages |
| Public site (future) | Only for genuinely interactive features (e.g. booking), loaded on the specific page/section that needs it, never globally |
| Preview | Server-rendered theme output (same renderer); the dashboard chrome around it may use Livewire |
| Dashboard | Livewire + Flux (starter kit) |

## 4. SEO Requirements

All SEO data is built by the renderer into an `SeoData` value object that is part of `SitePageData` (0.5 §6). Theme layouts print it; they never compute it.

### 4.1 Document metadata

| Element | Source / rule |
|---|---|
| `<html lang>` | Site `locale` |
| `<title>` | `seo_title`, else company name. Guidance ≤ 60 characters (dashboard hint, not hard limit). No platform branding by default |
| `<meta name="description">` | `seo_description`, else Hero subheadline, else About body truncated to ~155 characters |
| `<link rel="canonical">` | `SiteUrlGenerator::canonical()` — `https://{subdomain}.{tenant_domain}/` in MVP; primary custom domain in Phase 5. Query strings never part of the canonical |
| `<meta name="robots">` + `X-Robots-Tag` | `index, follow` for publicly visible pages; `noindex` for preview, privacy page, error pages and all non-200 responses; global `noindex` switch for non-production environments (§4.5) |
| `<meta name="theme-color">` | From the active theme preset |

### 4.2 Open Graph & social cards

| Property | Value |
|---|---|
| `og:type` | `website` |
| `og:title`, `og:description` | Same as title / description |
| `og:url` | Canonical URL |
| `og:image` (+ width/height/alt) | OG image media, else logo; absolute URL; 1200×630 variant generated on upload |
| `og:locale` | Site locale (e.g. `tr_TR`, `en_US`) |
| `og:site_name` | Company name |
| `twitter:card` | `summary_large_image` when an OG image exists, else `summary` |

### 4.3 Structured data (JSON-LD)

| Item | Rule |
|---|---|
| Type | `LocalBusiness` (or a more specific schema.org subtype mapped from the industry, e.g. `LegalService`, `Florist`, `Restaurant`) when a primary location exists; otherwise `Organization` (S-3) |
| Properties | `name`, `url` (canonical), `logo`, `image`, `telephone`, `email`, `address` (`PostalAddress` from primary location), `sameAs` (social links), `foundingDate` (`established_year`) |
| Omitted | Empty values; offerings markup (`makesOffer`) is a future enhancement |
| Encoding | `json_encode` with the flags `JSON_HEX_TAG`, `JSON_HEX_AMP`, `JSON_HEX_APOS`, `JSON_HEX_QUOT` and `JSON_UNESCAPED_UNICODE` so tenant text can never close the `<script>` element |
| Industry mapping | Code-level map from industry slug to schema.org type, fallback `LocalBusiness` |

### 4.4 Content semantics

| Rule | Detail |
|---|---|
| One `<h1>` | Hero headline |
| Section headings | `<h2>`; item headings `<h3>` |
| Landmarks | `<header>`, `<nav>`, `<main>`, `<footer>` |
| Anchors | Stable section anchors (`#about`, `#services`, `#contact`) used by navigation and CTA |
| Images | Meaningful `alt` from media alt text; decorative images `alt=""` (0.5) |
| Links | External social links with `rel="noopener"`; visible link text |

### 4.5 Indexing controls

| Case | Behavior |
|---|---|
| Publicly visible site | Indexable |
| Preview (platform host) | `noindex, nofollow` (0.4 §7.4) |
| Privacy page | `noindex, follow`; excluded from sitemap (template text is near-identical across tenants) |
| Non-production environments | Configuration switch (e.g. `firmhub.tenant_indexing=false`) forces `noindex` and `Disallow: /` on all tenant hosts — staging and self-hosted test instances must never be indexed |
| Dashboard / auth pages | `noindex`; disallowed in platform `robots.txt` |
| Quarantined subdomain | `301` to the current site (0.4 §5) |
| Phase 5 custom domain | Canonical = primary domain; subdomain and secondary domains `301` to it |

### 4.6 Icons

Tenant layouts declare `icon`, `apple-touch-icon` and manifest-free icon links from the site favicon variants. When a site has no favicon, a neutral default icon is used — not the FirmHub logo (avoids implying platform endorsement). Serving a tenant-specific `/favicon.ico` route is optional (Phase 3 decision); the static platform file remains the fallback.

## 5. Robots, Sitemap, Status Codes & Errors

### 5.1 `robots.txt`

- **Static `public/robots.txt` must be removed** (Phase 3) so the request reaches the application.
- Tenant host, visible site: `User-agent: *`, `Allow: /`, `Sitemap: {canonical}/sitemap.xml`.
- Tenant host, not visible: `404` (consistent with 0.4 SD-1).
- Platform host: disallow `/dashboard`, `/admin`, `/settings`, auth routes; allow marketing pages.
- Non-production: `Disallow: /` everywhere.

### 5.2 `sitemap.xml`

- Per tenant host; contains only that site's indexable URLs. In the MVP this is the home page only.
- `lastmod` = site `content_updated_at` (§7.4).
- No cross-tenant sitemap index; the platform marketing sitemap is separate.

### 5.3 HTTP status codes

| Code | Use |
|---|---|
| `200` | Visible page |
| `301` | Quarantined subdomain, future canonical-domain redirects, URL normalization (e.g. `/index.php` → `/`) |
| `303` | Successful contact submission (PRG) |
| `304` | Conditional request matches `ETag` / `Last-Modified` |
| `404` | Unknown/non-visible site, unknown path |
| `405` | Wrong method (framework default) |
| `422` | Contact validation errors (re-rendered page) |
| `429` | Contact rate limit |
| `503` | Platform maintenance mode (`Retry-After`) |

`410 Gone` is not used in the MVP: a deleted company may be restored during its grace period, and non-visible states must be indistinguishable (0.4 §6).

### 5.4 Error pages

| Context | Page |
|---|---|
| Host not resolved / site not visible | Generic, neutral "site not found" page; no tenant data; `noindex` |
| Visible site, unknown path | Tenant-themed 404 with link to home (S-6) |
| Server error on a tenant host | Generic error page; never exposes stack traces or other tenants' data |
| Platform host | Existing platform error pages |

The exception handler selects the error view from the request context (`CurrentSite` present or not).

## 6. JavaScript Policy (Public Sites)

| Rule | Detail |
|---|---|
| JS-1 | Public pages work completely without JavaScript |
| JS-2 | Mobile navigation uses a CSS/HTML solution (e.g. `<details>`/`<summary>`) or an optional tiny progressive-enhancement script (≤ 5 KB, theme-owned) |
| JS-3 | No third-party scripts: no analytics, tag managers, chat widgets, map embeds, font CDNs (privacy and performance) |
| JS-4 | No inline scripts other than the JSON-LD data block (CSP-friendly, §8) |

## 7. Performance Strategy

### 7.1 Targets

| Metric | Target (proposal) | Notes |
|---|---|---|
| LCP | < 2.5 s (mobile, p75) | Core Web Vitals "good" (0.1 NFR-PERF-01) |
| INP | < 200 ms | Trivially met without JS |
| CLS | < 0.1 | Explicit image dimensions, font fallback metrics |
| Origin response time (uncached) | p95 < 200 ms | Fixed query budget |
| Queries per page | ≤ 5 | 0.5 §6, asserted in tests |
| JavaScript | 0 KB required (≤ 5 KB optional) | JS-1, JS-2 |
| Theme CSS | ≤ 30 KB compressed | Tailwind v4 output per theme |
| Fonts | ≤ 2 families, `woff2`, ≤ 4 files | `font-display: swap` |
| Hero/LCP image | ≤ ~150 KB at 960 px | WebP variants (0.5 §7.1) |
| Lighthouse (mobile) | Performance, Accessibility, SEO, Best Practices ≥ 90 | Manual check per theme in Phase 3; automated in CI later |

### 7.2 Images

- `srcset`/`sizes` from WebP variants; `width`/`height` attributes always set.
- Hero image: `fetchpriority="high"`, never lazy-loaded.
- Below-the-fold images: `loading="lazy"`, `decoding="async"`.

### 7.3 CSS & fonts

- One CSS file per theme; theme presets compiled into that CSS as attribute-scoped custom properties (e.g. `[data-preset="ocean"] { --color-primary: … }`). Presets are a finite, code-defined set (0.5 §5.2), so **no inline styles** are needed — keeps CSP strict.
- Self-hosted fonts; primary font preloaded; fallback font metric overrides (the existing `fontaine` dev dependency can generate them) to minimize CLS.

### 7.4 HTTP caching

| Resource | Policy |
|---|---|
| Public HTML | `Cache-Control: public, max-age=60` (proposal) + `ETag`/`Last-Modified` from `content_updated_at`; conditional requests return `304` |
| `robots.txt`, `sitemap.xml` | Same as HTML |
| Hashed build assets | `public, max-age=31536000, immutable` (web server configuration) |
| Media files | Long-lived; unique paths per upload make them immutable |
| Preview & dashboard | `private, no-store` |

**Proposed schema refinement to 0.3:** add `company_sites.content_updated_at` (`timestamptz`), bumped in the same transaction as any change to site settings, sections, offerings, branding, company public fields or primary location. It drives `ETag`, `Last-Modified`, sitemap `lastmod` and future cache keys.

Server-side full-page caching is **not** part of the MVP (file cache, single server). If metrics require it later, cache entries are keyed by site ID + `content_updated_at`, so every content change invalidates automatically. With the live content model (0.4 P-1), a 60-second browser cache is the maximum staleness after an edit.

### 7.5 Asset delivery

- MVP: root-relative build assets served from the requesting host (tenant hosts point at the same server); no CORS needed for fonts.
- Compression (Brotli/gzip) and HTTP/2+ at the web server / reverse proxy.
- Future: `ASSET_URL` / media disk URL pointing at a CDN (requires CORS headers for fonts and CSP updates).

## 8. Security Headers on Public Pages (Rendering-Related Summary)

Finalized in 0.7; listed here because rendering choices depend on them.

| Header | Intended value |
|---|---|
| `Content-Security-Policy` | `default-src 'none'; style-src 'self'; font-src 'self'; img-src 'self' {media origin} data:; form-action 'self'; base-uri 'none'; frame-ancestors 'none'` — possible because there are no inline scripts/styles and no third parties. JSON-LD data blocks are not executed; their interaction with CSP must be verified |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | Deny unused features (camera, microphone, geolocation, …) |
| `Strict-Transport-Security` | Production, per domain decision (0.4 §8.3) |

## 9. Multi-Tenant Rendering Safety

| ID | Rule |
|---|---|
| MT-1 | All page data, metadata, URLs and structured data come from the single resolved site's `SitePageData`; no global state |
| MT-2 | Canonical, OG and sitemap URLs come only from `SiteUrlGenerator` (never from the `Host` header, 0.4 HH-2) |
| MT-3 | Media URLs in the page belong to the site's company (0.5 §4.5) |
| MT-4 | Any cache key for rendered output or fragments includes the site ID |
| MT-5 | Tests render two tenants and assert that neither page contains the other's name, URLs, media or contact data |

## 10. Accessibility Requirements

Target: **WCAG 2.2 AA** for public themes and the dashboard.

| Area | Requirement |
|---|---|
| Structure | Landmarks, single `<h1>`, ordered headings, skip-to-content link, `lang` attribute |
| Color | Every theme preset pre-validated for contrast (≥ 4.5:1 text, ≥ 3:1 large text and UI). Users cannot choose arbitrary colors in the MVP, which makes this guaranteeable |
| Keyboard | All interactive elements reachable and operable; visible focus indicator; mobile navigation keyboard-accessible |
| Forms | Visible labels, required-field indication, errors linked with `aria-describedby`, error summary on `422` re-render, success message announced (`role="status"`) |
| Images | Alt text rules (0.5); no text baked into images required for understanding |
| Motion | Respect `prefers-reduced-motion`; no autoplay media |
| Target size | Interactive targets ≥ 24 × 24 CSS px (WCAG 2.2 SC 2.5.8) |
| Zoom / reflow | Usable at 200 % zoom and 320 px width without horizontal scrolling |
| Dashboard | Flux components plus custom views checked against the same criteria; editors give character counts and clear error messages |
| Verification | Automated checks (tool decision in 0.8/0.9) + manual keyboard and screen reader smoke test per theme |

## 11. Localization on Public Sites

- Static strings from `lang/{site locale}/site.php` (0.5 TH-5); dates and numbers formatted with the site locale.
- `og:locale` and `<html lang>` from the site locale.
- `hreflang` is not applicable (one language per site); required once multilingual content arrives.
