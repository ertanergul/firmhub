## 2. Principles

| ID | Principle |
|---|---|
| TP-1 | **Real PostgreSQL only.** No SQLite test runs; constraints, partial indexes, `jsonb`, advisory locks and `FOR UPDATE` behave differently or not at all elsewhere (prompt §4.3, 0.3 §10) |
| TP-2 | **Behavior over declarations.** Tests send requests or call actions and assert responses and persisted state; they do not assert that a rule array contains a string. Architecture tests are the deliberate exception (§4.8) |
| TP-3 | **Feature tests first.** Unit tests only for framework-free logic (normalizers, token signing, value objects) |
| TP-4 | **Every security decision has a failing-path test** — the denied role, the foreign tenant, the invalid input — not only the happy path |
| TP-5 | **Deterministic.** Time frozen where it matters, no network, no real sleeps, framework fakes for mail/notifications/storage |
| TP-6 | **Follow existing conventions** (`test()` style, `Livewire::test('pages::…')`); the existing starter-kit tests are kept unchanged |
| TP-7 | **One defect, one owner.** Matrices (roles × abilities, valid/invalid subdomains) live in the lowest layer that owns the rule; endpoint tests keep one representative case to prove the rule is applied |
| TP-8 | **A task is not done until its tests run green** on PostgreSQL; unrun tests are never reported as passing (prompt §2.3 D) |

## 4. Test Types

### 4.1 Overview

| Type | Purpose | Location | Tooling |
|---|---|---|---|
| Unit | Framework-free logic | `tests/Unit/…` mirroring `app/` | Pest |
| Feature — HTTP | Routes, middleware, controllers, public site, headers | `tests/Feature/Http/…` | Laravel HTTP tests |
| Feature — Livewire | Dashboard pages and actions, including direct action calls | `tests/Feature/Pages/…` mirroring `resources/views/pages/…` | `Livewire::test` |
| Feature — Actions & policies | Business rules, transactions, authorization matrices | `tests/Feature/Actions/…`, `tests/Feature/Policies/…` | Pest + factories |
| Database | Constraints, cascades, partial indexes (PostgreSQL) | `tests/Feature/Database/…` | Query builder inserts bypassing validation |
| Concurrency | Row locks and advisory locks under contention | `tests/Feature/Concurrency/…`, group `concurrency` | Two DB connections, committed data (§5.3) |
| Rendering | Public output, tenant separation, query budget, SEO tags | `tests/Feature/Rendering/…` | HTTP tests + query counting |
| Architecture | Conventions and module boundaries | `tests/Arch/…` (new suite) | Pest `arch()` + presets |
| Console / scheduler | Admin commands, purge jobs | `tests/Feature/Console/…` | `artisan()` test helper, time travel |
| Browser / accessibility | Real-browser a11y checks of themes | `tests/Browser/…` | **Deferred** (0.8 ND-3, needs approval) |
| Manual | Lighthouse, keyboard/screen reader, Safari `*.localhost`, email rendering, TLS | Checklist in task report | §10 |

**Layout rule (refines 0.8 §6.2):** test files mirror the class or page under test (`app/Actions/Companies/CreateCompany.php` → `tests/Feature/Actions/Companies/CreateCompanyTest.php`). Cross-cutting suites (`Database`, `Concurrency`, `Rendering`, `Security`) group tests that span several classes.

### 4.2 Authorization tests

| Layer | What is asserted |
|---|---|
| Policy | Full role × ability matrix from 0.2 §7 as an explicit dataset (expected values written in the test, **not** derived from `CompanyRole` — otherwise the test repeats the implementation) |
| Endpoint / Livewire action | One denied role → `403`; one non-member → `404`; one allowed role → success and persisted state |
| Route inventory | Architecture-style test iterating registered routes: every `/dashboard/{company}/…` route has `auth`, `verified` and `EnsureCompanyMembership` (0.2 AR-1) |

### 4.3 Tenant isolation tests (0.2 AR-14)

For **every** tenant-owned resource:

1. Read, update and delete through the route/action as a member of company B targeting company A's record → `404`, record unchanged.
2. Livewire action called directly with a foreign record ID (bypassing the UI) → refused, unchanged.
3. Attaching a foreign record by ID in input (media, location, offering) → validation error.
4. `company_id` / `company_site_id` / `role` in the payload → ignored or rejected (mass assignment).

A shared helper (e.g. `memberOf(Company $company, CompanyRole $role): User`) and datasets keep these tests short. A **checklist in the Phase 2/3 task reports** lists each tenant resource and its isolation tests.

### 4.4 Livewire tests

- Call every public action directly with `Livewire::test(...)->call(...)` as an unauthorized user (0.2 AR-3, T-4).
- Attempt to set `#[Locked]` properties from the test client and assert the exception (*verify* Livewire 4 behavior and exception type).
- Assert validation errors per field and that nothing persisted on failure.
- Temporary upload rules (size, type) exercised with `UploadedFile::fake()` and real fixture files (§6).

### 4.5 Public site & rendering tests

| Area | Tests |
|---|---|
| Host resolution | Platform host, valid/invalid labels, uppercase host, trailing dot, multi-level host, unknown host, untrusted host (0.4 §13) |
| Visibility matrix | Dataset over `status` (draft/published/unpublished) × site suspended × company suspended × company soft-deleted = 24 cases; only `published` + all-clear returns `200` |
| Indistinguishability | Non-visible states return identical status, body and relevant headers (0.4 D-3) |
| Quarantine | `301` with path preserved; same-company reclaim; other-company rejection; expiry via time travel |
| Two-tenant leakage | Render A and B; neither response contains the other's name, URLs, media or contact data (0.6 MT-5) |
| Query budget | Public page ≤ 5 queries (0.5 §6) asserted by counting executed queries |
| SEO output | Title/description fallbacks, canonical from `SiteUrlGenerator` (not from `Host`), OG tags, JSON-LD escaping, robots/`X-Robots-Tag` per state, `robots.txt`, `sitemap.xml` (0.6 §4–5) |
| Statelessness | Public responses set no cookies (0.6 §3.2) |
| Headers | Public CSP and baseline headers; preview `no-store` + `noindex` (0.7 SEC-HDR) |
| Errors | Unknown path on a visible site → tenant-themed 404; non-visible host → generic 404 |

### 4.6 Database tests (PostgreSQL)

Insert through the query builder (bypassing validation) and assert the database rejects invalid data:

| Constraint (0.3 / 0.4) | Expected |
|---|---|
| UQ `company_memberships (company_id, user_id)` | Unique violation (SQLSTATE `23505`) |
| UQ `company_sites (company_id)` (MVP single site) | `23505` |
| UQ `company_sites.subdomain`; subdomain CHECK regex, `--`, numeric-only | `23505` / `23514` |
| Partial UQ primary location; partial UQ pending invitation | `23505`; closed invitations do not conflict |
| Composite FKs (media, site ↔ company) with a foreign company's ID | FK violation `23503` |
| `ON DELETE SET NULL (column)` keeps `company_id` intact | Row kept, only the media column nulled |
| CHECKs: lowercase email, role values, `published ⇒ published_at`, not accepted + revoked | `23514` |
| Cascades that encode application behavior (company purge removes tenant rows; site deletion keeps messages with `company_site_id = NULL`) | Asserted as behavior |

Application code converts `23505` into validation errors; that conversion is tested at the action level (subdomain claim, site creation).

### 4.7 Security tests

The full list from 0.7 §11 is adopted. Additional rules:

- XSS payloads (`<script>`, attribute breakers, `javascript:` URLs, JSON-LD `</script>` breakout) go through **every** free-text field rendered in public themes, dashboard views **and** notification mails; assert the escaped form is present and the raw payload absent.
- Forged `Host` / `X-Forwarded-Host` on password reset and invitation flows; links must use `APP_URL` (0.7 SEC-HOST-1).
- Contact form: missing, expired, tampered and too-fast tokens; honeypot silent discard; `429`; foreign `Origin`; CR/LF in single-line fields; no IP persisted (0.7 SEC-CONTACT, PRIV-1).
- Media: fixture-based rejection tests (§6).

### 4.8 Architecture tests (`tests/Arch`)

| Rule | Protects |
|---|---|
| Pest `security` preset (no `eval`, `md5`, `exec`, …) and `php` preset; `laravel` preset only if its expectations fit the project (*verify* preset contents) | Baseline hygiene |
| No `dd`, `dump`, `ray`, `var_dump` in `app/` | Debug leftovers |
| Every model in `app/Models` used for tenant data has a policy (0.7 SEC-AUTHZ-1) | Authorization coverage |
| `App\Themes` and theme view models do not use `App\Models` or `Illuminate\Support\Facades\DB` (0.8 MB-1) | Theme isolation |
| Tenant rendering (`App\Support\Rendering`, `Http\Controllers\Tenant`) does not use `CurrentCompany`, session or Livewire (0.8 MB-2, MB-4) | Public/dashboard separation |
| Enums are backed enums; actions are invokable or expose one public `handle()` method (convention fixed in Phase 2) | Consistency |
| Blade scan: no `{!!` in `resources/views` outside an explicit allow-list (0.7 SEC-CONTENT-1) | XSS |

### 4.9 Console & scheduled jobs

Purge commands (messages 24 months, invitations 90 days, companies 30 days, orphan media 24 h, released subdomains) tested with `travel()` / `travelTo()`: records just inside the window stay, records just outside are deleted, files are removed from the faked disk. Platform admin commands: grant refused without 2FA (0.7 SEC-ADMIN-1); suspension logs actor and reason.

## 5. Database & Concurrency Testing Strategy

### 5.1 Refresh strategy

- Keep `RefreshDatabase` for `tests/Feature` (existing convention; each test runs in a transaction that is rolled back).
- **Option:** switch to `LazilyRefreshDatabase` so tests that never touch the database skip migrations. Small speed gain; changes the existing convention → decision Q-2.

### 5.2 Migrations

| Check | Where |
|---|---|
| `migrate:fresh` succeeds on an empty PostgreSQL 18 database | CI (implicit via `composer setup` and `RefreshDatabase`) |
| `migrate:rollback` back to zero, then `migrate` again | CI step proposed for Phases 1–3 (pre-production), so raw-SQL constraints have working `down()` methods (Q-3) |
| Migrations reviewed for raw SQL tested by §4.6 | Code review |

### 5.3 Concurrency tests

`RefreshDatabase` wraps each test in a transaction, so a second connection cannot see uncommitted rows. Concurrency tests therefore:

1. Live in `tests/Feature/Concurrency`, tagged with the group `concurrency`.
2. Use a committed-data strategy (`DatabaseTruncation` or `DatabaseMigrations`, *verify* trait behavior with PostgreSQL) instead of `RefreshDatabase`.
3. Open a **second named connection** (same config, different name) and interleave steps deterministically in a single process: connection A begins a transaction and takes the lock; connection B runs the competing statement with a short `lock_timeout` (or `NOWAIT`) and the test asserts it blocks/fails; A commits; B retries and observes the committed state. No threads, sleeps or forks.

| Scenario | Source | Assertion |
|---|---|---|
| Two Owners demote each other concurrently | 0.2 RM-2 | At least one Owner remains |
| Two claims of the same subdomain | 0.4 §5.2 | Exactly one succeeds; the other gets a validation error |
| Two site creations for one company | 0.3 §10 | One site exists |
| Accepting the same invitation twice | 0.3 §10 | One membership; second acceptance idempotent |
| Concurrent section reorder | 0.3 §10 | Final order consistent (no duplicate/missing positions) |
| Optimistic concurrency on section save (Should) | 0.5 UX-4 | Stale `updated_at` produces a conflict, no overwrite |

## 6. Test Data & Fixtures

| Item | Rule |
|---|---|
| Factories | One per model with meaningful states: `CompanyFactory` (`suspended`, `deleted`, `onboarded`), `CompanyMembershipFactory` (`owner`, `admin`, `editor`, `viewer`), `CompanySiteFactory` (`draft`, `published`, `unpublished`, `suspended`), `CompanyInvitationFactory` (`expired`, `accepted`, `revoked`), `CompanyMediaFactory`, `CompanyContactMessageFactory` |
| Ownership consistency | Factories create children for the **same** company (e.g. a site's media belongs to the site's company); cross-tenant records are always created explicitly in the test |
| Helpers | `memberOf($company, $role)`, `publishedSite()`, `tenantUrl($site, $path)` in `tests/Pest.php` (or a `tests/Support` file) |
| Image fixtures (`tests/Fixtures/media/`) | Small JPEG/PNG/WebP; JPEG with GPS EXIF; SVG with script; PHP/HTML file renamed to `.jpg`; polyglot image; PNG whose header declares > 25 MP; corrupt image; GIF/HEIC (unsupported) |
| Time | `freezeTime()` for token age, invitation expiry, quarantine, cooldown, retention |
| Seeders | `IndustrySeeder` is part of the application (production data); demo seeders for local use only, never relied upon by tests |

| Dependency | Strategy |
|---|---|
| Outbound HTTP | `Http::preventStrayRequests()` globally; exact-endpoint fakes per test (HIBP in production password policy tests, Phase 5 Cloudflare) |
| Sleep / retries | `Sleep::fake()` globally (*verify* signature) |

## 9. Quality Gates

### 9.1 Gate levels

| Level | When | Checks | Blocking |
|---|---|---|---|
| G1 — Change | While implementing | Narrowest relevant Pest tests; `vendor/bin/pint --dirty` | Developer |
| G2 — Task completion | Before the task report (prompt §2.3 D/E) | Full Pest suite on PostgreSQL; Pint; Larastan; `npm run build` when frontend changed; migrations fresh + rollback when migrations changed; audits when dependencies changed | Yes — failures reported, task not marked done |
| G3 — Pull request (CI) | Every PR to `develop` / `main` | Pint check, Larastan level 7, Pest (incl. arch and concurrency groups), frontend build, `composer audit`, `npm audit --audit-level=high` (after 0.8 MD-1 is resolved), migration rollback check | Yes — required status checks (branch protection is a repository setting the owner configures) |
| G4 — Periodic | Weekly or before a release | `pest --profile` (slow tests), mutation testing (`--mutate`) on policies, actions and rules; Dependabot PR review; coverage report | No — findings become tasks |
| G5 — Release / Phase gate | End of Phase 3 and Phase 7 | Manual checklist (§10), security checklist (0.7 §9), staging verification | Yes |

### 9.2 Coverage policy

- Code coverage is **reported, not enforced** in Phases 1–3 (pcov is available in the Sail image; CI currently runs `coverage: none`).
- Critical areas are protected by the explicit matrix (§8) and mutation testing (G4), which measure test quality better than a global percentage.
- A minimum threshold for `app/Policies`, `app/Actions` and `app/Rules` may be introduced after Phase 3 (Q-4).

### 9.3 Suite performance

- Already in place: `BCRYPT_ROUNDS=4`, array cache/session/mail, Xdebug off by default in Sail.
- Measure with `--profile` before optimizing; then consider `--parallel` (§3) and cached config/routes traits (*verify* availability in Laravel 13).
- Target: full suite under 2 minutes in CI through Phase 3 (proposal).

## 11. Definition of Done (per implementation task)

1. Acceptance criteria of the task met.
2. Tests for every new decision (§8 rows touched by the task) written and passing on PostgreSQL.
3. Tenant isolation checklist completed for every new tenant resource (§4.3).
4. Pint, Larastan and the full Pest suite green (G2); frontend build green when relevant.
5. No new dependency without approval; audits clean or findings reported.
6. Report lists every check actually run, with results; skipped checks named explicitly.
